User-Frage war: „Wie sieht es mit gescoptetem CSS aus und Source-Dateien wie bei Blazor (AddressEditor.tazor.ts / AddressEditor.tazor.css)?"

### 1. Scoped CSS (`X.tazor.css`) — Empfehlung: zuerst bauen

Blazor-Mechanismus 1:1: Markup-Emission bekommt Scope-Attribut `b-<hash>` (Hash deterministisch aus Dateipfad), CSS-Rewriter hängt `[b-<hash>]` an jeden Compound-Selektor (`.a > .b:hover` → `.a[b-x] > .b[b-x]:hover`), `@media` durchlaufen, `@keyframes` unberührt. `::deep` wie Blazor: Attribut nur auf Selektoren *vor* dem `::deep`, danach Descendant-Kombinator (`[b-x] .child`). Injection via `import "./X.tazor.css"` im Codegen — Vite erledigt dev/build.

- Runtime-Anteil: keiner. Compiler-Anteil: eine Emission-Änderung.
- Der eigentliche Aufwand: robuster Selektor-Rewriter → **postcss als Dependency** (statt Regex) vorgeschlagen.

### 2. Code-behind (`X.tazor.ts`) — danach ~~(offen)~~ → **erledigt 2026-09-29**

TS hat keine partial classes → Abbildung über Vererbung:
`X.tazor.ts` exportiert `export default class XCode extends ComponentBase {...}` (deklariert eigenen `extends`, auch @inherits-Ketten: generated → code-behind → Basis). Compiler erkennt `X.tazor.ts` neben `X.tazor`, importiert Default-Export, emittiert `extends`.

- **Runtime-seitig gratis verifiziert**: `findParameterMetadata` (packages/runtime/src/components/parameter-metadata.ts:33) läuft bereits die Prototype-Chain → `@Parameter()` in der Code-behind-Klasse funktioniert heute.
- Abweichung zu Blazor dokumentieren: kein `partial`, sichtbare Basisklasse.

### Offene Design-Entscheidungen beim Start zu klären

1. ~~postcss als Dependency ja/nein~~ → **entchieden: postcss** (dependency, beim Bundle `--external:postcss`, zur Laufzeit über Pluging-Deps auflösbar)
2. ~~Basis des Scope-Hashes~~ → **entchieden: repo-relativer POSIX-Pfad** (sha1, 8 Hex)
3. ~~`_Imports.tazor`-Interaktion~~ → pro Datei gescopt (Realität: `_Imports` ist nur Using-Manifest, Seiten liegen als eigene Dateien)
4. Soll Tasor beim async-Lifecycle-Fall komfortabler sein als Blazor (auto-Re-Render nach await)? — offen seit Pizza-Port, in port-findings.md §A.3 vermerkt
