# Port: BlazorHero → Tsazor

The second app port before 1.0 (owner, 2026-10-12), after [FluentCMS](port-fluentcms.md). Where FluentCMS was a
Blazor Server admin behind a cookie BFF, BlazorHero is the typical Blazor WebAssembly app of a .NET team from
2021–2023: [fullstackhero/blazor-starter-kit](https://github.com/fullstackhero/blazor-starter-kit) (MIT), hosted
WebAssembly on MudBlazor 6, Identity with JWT and refresh tokens in the browser, SignalR (chat, notifications),
localization (resx, eleven languages, Arabic right-to-left), a dashboard with charts, server-paged tables with Excel
export and import.

The rule is FluentCMS's: the backend stays unchanged, every gap becomes a framework fix with a test, every lesson
goes into [migration-practices.md](migration-practices.md). The freeze signal is FluentCMS's too: the public API
stops moving while the port goes on, judged with a sense of proportion
([port-fluentcms.md](port-fluentcms.md)).

## Setup

- **Upstream:** commit `11f810d` (2022-07-23, the last on `master`), cloned into `apps/blazorhero/.backend/`
  (git-ignored) by `pnpm --filter blazorhero backend`.
- **Toolchain:** BlazorHero builds only with the .NET 6 SDK (B1). The script installs it into `.backend/dotnet` with
  Microsoft's dotnet-install script — no admin, nothing system-wide — and runs BlazorHero on its own runtime.
- **Database:** SQL Server LocalDB, a database of its own (`TsazorBlazorHero`) through the connection string;
  `--reset` drops it, and BlazorHero's seeder fills a new one (users `mukesh@blazorhero.com` and
  `john@blazorhero.com`, password `123Pa$$word!`).
- **Ports:** the backend on 5350 (its own WebAssembly client, the reference, at `/`; Swagger at `/swagger`), the
  Tsazor app's dev server on 5352.
- **Mail:** BlazorHero's appsettings name an ethereal.email account; the script sets the mail host to a port on this
  machine where nothing listens, so a registration's confirmation and a reset link go nowhere (BlazorHero logs the
  failed send). The reset link stays in the job Hangfire stored, where `verify.mjs` reads its token (`sqlcmd`).

## Phases

0. **Backend and reference** — done 2026-10-12: the script, the original client signs in and shows its shell.
1. **Shell and sign-in** — done 2026-10-12 (`scripts/verify.mjs`, 38 checks): layout (app bar, nav menu, user
   card, dark mode, language selector), login with the JWT and its refresh token, Home; the original's managers and DTOs as TypeScript (B3). The shell already holds
   the SignalR connection (sign-in at the hub, chat notifications, forced token refresh, logout when a role's
   permissions change) and reads every text through its localizer, so both start here:
   - **Translations** (done 2026-10-12): `scripts/resx.mjs` turns the 39 resources into one table per culture
     (`src/i18n`, keys `<Resource>.<name>`) — 505 keys in English, 266 in German.
2. **Catalog** — done 2026-10-12 (`scripts/verify.mjs`, 66 checks with phase 1): brands and products —
   server-paged tables with search, add/edit dialogs, delete confirmation, Excel export and import. Brands are a
   DataGrid of the filtered list (MudTable Items + Filter), products one with an ItemsProvider (ServerData); the
   product dialog picks its brand in an Autocomplete and shrinks the picture with `requestImageFileAsync`.
3. **Identity** — done 2026-10-21 (`scripts/verify.mjs`, 153 checks with every phase): the users — their flags in
   read-only boxes (B48), searched, exported (the API answers the workbook as text, B49), one registered in the
   dialog, a user's profile with the administrator's activation (AuthorizeView Roles); the roles — added and edited in
   the dialog, refused for deletion while a user has one (U17); a role's permissions, a tab per group with its
   "selected/all" badge, ticked and commented in a row's edit (B50), saved — every client renews its token by the hub;
   a user's roles; the user signed in with the role's page in the menu, the account (the picture shrunk and uploaded,
   then deleted; the details, which sign out; the password); signed out, the password forgotten and reset by the
   mail's link (U15), and the sign-up, whose user stays inactive. The API deletes no users: each run leaves two.
4. **Documents and audit** — done 2026-10-21 (`scripts/verify.mjs`, 103 checks): the document types (dialog, the
   validators' messages); the document store, a page at a time from the API, a document with its type picked in an
   Autocomplete and its file uploaded, its Download a link entry; its extended attributes — the original's abstract
   generic ExtendedAttributesBase, a code-only class that hands its markup on, and the document's page with markup of
   its own (B38) — a tab per group with an "active/all" badge that follows the attributes (B41), a text and a
   Decimal attribute; the audit trails searched by table name and date range, a trail's details.
5. **Real time** — done 2026-10-21 (`scripts/verify.mjs`, 83 checks with phases 1 and 2): the dashboard — the counts
   as tiles, what was added each month as a bar chart (`@tsazor/charts`), the hub's UpdateDashboard from a brand
   saved in another tab — and the chat, with a second user in a browser context of its own (the run gives the basic
   role the chat's permission and takes it back): who is online by the hub (ConnectUser, the ping, DisconnectUser),
   a message on both sides at once, the receiver's notification with its "Chat?", the contacts in a Drawer on a
   narrow window.
6. **Languages** — done 2026-10-21 (`scripts/verify.mjs`, 90 checks): each of the eleven loads the app in it (the
   page's language, the navigation's headings from its table, the API asked in it), the preference stored as the
   original stores it (B33), Arabic right to left on the products, the dashboard and the chat (the navigation on the
   right, the pager's arrows mirrored, axe). Compared with the original in Arabic: both mirror the frame, the tiles
   and the toolbar; neither mirrors the chart's month axis. The skins' right-to-left gaps it found are fixed (B35).

Each phase ends with its part of `scripts/verify.mjs` (the app in a browser against the real backend).

The menu links every page of the original, as the original's does. While phases were open, their pages said "Not
ported yet" (the owner, clicking through, had taken the "doesn't exist" page for a broken app, 2026-10-15); with
phase 3 every page is ported and the placeholder is gone.
